# 06. Разработка под Samsung Tizen TV

Главное отличие от веба: **нет мыши и тача — только пульт (D-pad + OK)**, слабое железо на старых моделях и специфика установки/провижининга. Это нужно учитывать с первого дня.

## Окружение разработчика

| Инструмент | Назначение |
|-----------|-----------|
| **Tizen Studio** | Официальная IDE: сборка `.wgt`, эмулятор, деплой на TV |
| **Samsung TV Emulator** | Тестирование без реального TV (входит в Tizen Studio) |
| **Tizen CLI** | Сборка/упаковка/подпись из командной строки (для CI) |
| **Samsung Developer Account** | Сертификаты, публикация |
| **Vite** | Сборка веб-части (TS → ES2017 бандл) перед упаковкой в `.wgt` |

**Поток сборки:** `vite build` (в `apps/tv-app/dist`) → `tizen package -t wgt` (подпись сертификатом) → `tizen install`/запуск в эмуляторе или на TV.

### Манифест `config.xml` (ключевое)
- `tizen:application id`, `package`, версия.
- `tizen:profile name="tv"`.
- Привилегии: `http://tizen.org/privilege/tv.inputdevice` (клавиши пульта), `internet`, `http://tizen.org/privilege/network.get` и др. по мере надобности.
- `tizen:setting screen-orientation="landscape"`.
- Минимальная версия платформы (`required_version`) — целимся в 4.0, мягко поддерживаем ниже.

## D-pad навигация (фокус-движок)

### Клавиши пульта
Регистрируем нужные клавиши через Tizen API и обрабатываем `keydown`:

```js
// регистрация дополнительных клавиш пульта (цветные, медиа) — базовые доступны всегда
if (window.tizen?.tvinputdevice) {
  ['ColorF0Red','ColorF1Green','ColorF2Yellow','ColorF3Blue','MediaPlayPause']
    .forEach(k => tizen.tvinputdevice.registerKey(k));
}
```

Коды клавиш (`keydown.keyCode`):
| Клавиша | keyCode |
|---------|---------|
| Влево / Вверх / Вправо / Вниз | 37 / 38 / 39 / 40 |
| OK (Enter) | 13 |
| Назад (Return) | **10009** |
| Exit | 10182 |
| Красная/Зелёная/Жёлтая/Синяя | 403 / 404 / 405 / 406 |

> **Back (10009) обязателен** — на каждом экране назад возвращает на предыдущий, на главном — диалог выхода. Без этого приложение «не отпускает» пользователя.

### Модель фокуса
- Все интерактивные элементы — фокусируемые (`tabindex="0"` или собственная модель), со стилем `:focus` (видимая рамка/масштаб).
- **Своя система spatial-navigation:** на нажатие стрелки ищем ближайший фокусируемый элемент в нужном направлении (по геометрии bounding box). Это надёжнее, чем полагаться на встроенную навигацию TV.
- Порядок фокуса — предсказуемый: слева-направо, сверху-вниз; «ловушки фокуса» (focus trap) в модалках.
- При открытии экрана — авт`focus()` на логичный первый элемент; при возврате — восстановить прежний фокус.

```js
// псевдокод фокус-движка
function onArrow(direction) {
  const current = document.activeElement;
  const next = findNearestFocusable(current, direction); // по геометрии
  if (next) next.focus();
}
```

### Экранная клавиатура
- Для PIN/кода брони/адреса — **своя экранная клавиатура** под D-pad (не системная), чтобы контролировать фокус и раскладку RU/EN/цифры.

## Провижининг (привязка TV к номеру)

**Скрытая критическая задача** (исправление недочёта исходного плана): без надёжной связки «этот TV = комната 305» не работает ни один модуль. Три способа, выбираем под отель:

| Способ | Как | Плюсы | Минусы |
|--------|-----|-------|--------|
| **A. Код-активация (рекомендуется)** | При установке сотрудник открывает приложение, вводит `provisionCode`, затем номер комнаты; сервер привязывает `deviceToken`↔`room` | Просто, без БД отеля; перенос/замена TV — повторная активация | Ручной шаг на каждый номер |
| **B. Конфиг при сборке/установке** | В образ/конфиг устройства зашит `room_id` (через MDM/SSSP) | Нет ручного шага в UI | Нужен MDM/Business TV, образ на номер |
| **C. MAC-маппинг** | Сервер хранит таблицу MAC TV → номер; устройство присылает MAC | Автоматизируемо | Требует инвентаризации MAC, привилегий на чтение сети |

**Рекомендация для пилота — способ A** (минимум зависимостей). `deviceToken` хранится в защищённом хранилище Tizen и используется для входа гостя.

**Сброс при выезде:** на Check-out гостевая сессия (JWT) инвалидируется, локальные данные гостя на TV очищаются, устройство остаётся привязанным к номеру (готово к следующему гостю).

## Бюджет производительности

Оцифровка вместо расплывчатого «избегать тяжёлых анимаций» (исправление недочёта). Цель — TV 2017 года, ~1 ГБ RAM:

| Метрика | Бюджет |
|---------|--------|
| TTI (Time To Interactive), холодный старт | **< 3 c** |
| JS-бандл (gzip) | **< 250 КБ** |
| CSS (gzip) | < 50 КБ |
| Память приложения (RSS) | **< 100 МБ** |
| Изображение блюда/товара | ≤ 1280 px, WebP/JPEG, ленивая загрузка, плейсхолдер |
| Анимации/переходы | целимся в 30 fps; только `transform`/`opacity` (GPU), без layout-трешинга |
| Шрифты | системные/один веб-шрифт ≤ 100 КБ |

**Практики:**
- Vanilla TS, без тяжёлых SPA-фреймворков (ADR-002); при необходимости компонентов — Preact (≈4 КБ).
- Виртуализация длинных списков (меню/каталог) — рендерить только видимое.
- Кэширование статики (меню/инфо) — работает офлайн (ADR-006).
- Предзагрузка изображений соседних карточек, освобождение далёких.
- Минимум таймеров/слушателей; снимать обработчики при уходе с экрана (нет утечек памяти — критично на TV, приложение живёт неделями).

## Доступность и UI для TV (10-foot UI)

Пользователь в 2–3 метрах от экрана с пультом:
- **Шрифт ≥ 24–28 px** для основного текста, заголовки крупнее.
- **Зона фокуса ≥ 48 px**, заметный фокус-стиль (рамка + лёгкий масштаб/тень).
- **Контраст ≥ WCAG AA** (4.5:1 для текста); тёмная тема комфортнее для ТВ-просмотра, но проверить читаемость.
- Не более ~3–5 уровней вложенности экранов; всегда видно «где я» и как назад.
- Без наведения-only (hover) взаимодействий — всё через фокус+OK.
- Учитывать **overscan**: безопасные поля ~5% по краям (старые TV обрезают края).
- Крупные «цели»: плитки модулей, кнопки — большие, далеко друг от друга.

## Локализация (i18n)

- Слой i18n с первого дня: все строки — через ключи (`t('food.cart.title')`), словари `ru.json`/`en.json`.
- Переключение языка на Lock-экране и в настройках; выбор хранится на устройстве и в профиле гостя.
- Форматирование дат/времени/валют — через `Intl` с учётом `hotel.timezone` и валюты.
- Тексты контента (меню, инфо) — локализованы в БД (`i18n jsonb`), а не в коде.

## Сетевая устойчивость на клиенте (ADR-006)

- **Статика** (меню, каталог, инфо, расписания) — кэш + `ETag`; показываем мгновенно, обновляем в фоне.
- **Мутации** (заказ, заявка, сообщение) — локальная **очередь** с `Idempotency-Key`; индикатор «отправляется → отправлено»; ретраи с backoff.
- **Экран «нет сети»** — явный, с автоповтором; не «вечный спиннер».
- WebSocket — авто-reconnect, после восстановления догрузка пропущенной истории чата/статусов.

| Сценарий | Что нужно |
|----------|-----------|
| **Прямая установка в отеле (рекомендуется для пилота)** | Developer/партнёрский сертификат; установка `.wgt` на TV; режим киоска |
