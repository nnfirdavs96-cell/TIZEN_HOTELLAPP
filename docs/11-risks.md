# 11. Риски

Расширенный реестр рисков (исходный план содержал 4 строки). Шкала: вероятность и влияние — низк./средн./выс. Приоритет = вероятность × влияние.

## Технические риски

| # | Риск | Вер. | Влияние | Митигация | Триггер/индикатор |
|---|------|------|---------|-----------|-------------------|
| T1 | **Разные модели TV ведут себя по-разному** (фокус, перф, API) | выс. | выс. | Тест на 3–5 реальных TV ([09](./09-testing-qa.md)); vanilla JS; бюджет перфа; feature-detection | Баги только на части моделей |
| T2 | **WebRTC/VoIP не работает на старых TV** | выс. | средн. | Деградация (ADR-005): чат + callback как основа, WebRTC опц. | Звонок не устанавливается на 2017–2019 |
| T3 | **Слабое железо → тормоза/утечки памяти** | средн. | выс. | Бюджет (<250 КБ, <100 МБ), виртуализация списков, soak-тест | TTI > 3 c, рост памяти за сутки |
| T4 | **Нет публичного API такси (Яндекс — B2B)** | выс. | средн. | `TaxiProvider` + dispatch-fallback (заявка ресепшену) | Нет договора с агрегатором к Фазе 3 |
| T5 | **Сложная/долгая интеграция с PMS (Opera/Fidelio)** | выс. | средн. | `PmsAdapter`; в MVP — экспорт счёта; глубокая интеграция после пилота (ADR-007) | Отель не даёт доступ к PMS API |
| T6 | **Нестабильная сеть в номерах → потеря заказов** | средн. | выс. | Офлайн-очередь + идемпотентность (ADR-006) | Жалобы на «пропавшие» заказы |
| T7 | **Провижининг номеров ненадёжен** (TV ↔ комната) | средн. | выс. | Способ A (код-активация), revoke/replace, мониторинг `last_seen` | Заказы привязываются к неверному номеру |
| T8 | **Сертификация Samsung затягивается** | средн. | низк. | Для пилота — Developer/Partner-сертификат, не Store | Долгая модерация Store |
| T9 | **Уязвимости/утечка PII или платёжных данных** | низк. | выс. | PCI SAQ-A (не храним карты), шифрование, RBAC, security-ревью ([08](./08-security-compliance.md)) | Находки аудита/сканеров |

## Продуктовые / бизнес-риски

| # | Риск | Вер. | Влияние | Митигация |
|---|------|------|---------|-----------|
| B1 | **Отель не хочет менять процессы** | средн. | выс. | Минимальная интеграция, charge-to-room поверх существующего фолио, обучение персонала |
| B2 | **Долгий цикл B2B-продажи** | выс. | средн. | Пилот на 1–2 мес. без обязательств; быстрый «time-to-value» |
| B3 | **Низкий adoption гостями** | средн. | выс. | Простой 10-foot UI, RU/EN, заметность на главном экране TV, замер KPI ([01](./01-overview.md)) |
| B4 | **Контент (меню/фото/инфо) не готов у отеля** | выс. | средн. | Шаблоны и помощь с наполнением; админ-панель для самостоятельного ввода |
| B5 | **Зависимость от одного пилотного отеля** | средн. | средн. | Параллельно вести 2 пилота; обобщать настройки в `hotel.settings` |

## Командные / процессные риски

| # | Риск | Вер. | Влияние | Митигация |
|---|------|------|---------|-----------|
| P1 | **Маленькая команда (2–3 чел.) → узкое место** | выс. | средн. | Приоритизация P0; единый стек (TS) для взаимозаменяемости; не брать P2 в MVP |
| P2 | **Размытие объёма (scope creep)** | средн. | выс. | Жёсткий объём MVP ([01](./01-overview.md)); новые идеи — в бэклог |
| P3 | **UI/UX на частичной занятости → задержки дизайна** | средн. | средн. | Дизайн ключевых экранов в Фазе 0 заранее; дизайн-система для переиспользования |
| P4 | **Технический долг из-за спешки к пилоту** | средн. | средн. | DoD, code review, тесты на P0-потоки; пост-пилотный рефакторинг-спринт |

## Топ-5 рисков под особым контролем

1. **T1 / T3** — зоопарк TV и производительность → ранний и регулярный тест на реальных устройствах.
2. **T2** — VoIP → не обещать заказчику то, что не работает везде; продавать чат+callback.
3. **T5 / B1** — PMS и нежелание менять процессы → charge-to-room + экспорт счёта, глубокая интеграция позже.
4. **T7** — провижининг → отдельная задача Фазы 0, надёжный способ A.
5. **B2 / B3** — продажа и adoption → быстрый пилот, измеримые KPI, простой UX.

## Процесс работы с рисками

- Реестр пересматривается на ретро каждого спринта.
- У каждого активного риска есть владелец и индикатор срабатывания.
- При срабатывании — фиксируем в issue, применяем митигацию, при необходимости пересматриваем план/объём.
