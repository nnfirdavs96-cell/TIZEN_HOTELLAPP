# 07. Дорожная карта и задачи

Детализация исходного плана до уровня спринтов и задач. Срок MVP: **6–10 месяцев**, команда **2–3 человека**. Добавлена **Фаза 0** (подготовка), которой не было в исходном плане.

Оценки — ориентировочные, в днях (д) команды. Приоритеты: **P0** (must для MVP), **P1** (should), **P2** (later). Спринт = 2 недели.

**Условные обозначения готовности:** ☐ не начато · ◐ в работе · ☑ готово.

---

## Definition of Done (на проект)

Задача считается завершённой, когда:
1. Код написан и проходит линт/типчек.
2. Покрыта тестами по уровню (unit для логики, e2e для критичных потоков — см. [09](./09-testing-qa.md)).
3. Работает **только пультом** (для TV-экранов) и на **RU/EN**.
4. Обрабатывает **офлайн/ошибки** (нет «вечных спиннеров»).
5. Code review пройден, ветка смержена в `develop` через PR, CI зелёный.
6. Критерии приёмки модуля (см. [03](./03-modules.md)) выполнены.

## Команда и процесс

- **Ветки (git-flow lite):** `main` (релизы) ← `develop` ← `feature/*`. Прямой push в `main`/`develop` запрещён, только через PR с зелёным CI и review.
- **PR:** небольшие, с описанием и чек-листом DoD; обязательный review второго участника.
- **Спринты:** 2 недели; в начале — планирование, в конце — демо + ретро.
- **Доска задач:** GitHub Projects / Issues, метки `P0/P1/P2`, `module:*`, `phase:*`.
- **Коммиты:** Conventional Commits (`feat:`, `fix:`, `docs:`…), привязка к issue.
- **CI:** на каждый PR — линт, типчек, тесты, сборка TV-`.wgt` и образов; см. [10](./10-deployment-ops.md).
